== 개요

chapchu-auth 명세입니다.

로그인과 회원등록은 이 서버가 담당하고, chapchu-api는 발급된 JWT의 서명만 검증합니다.
그래서 **chapchu-api 명세(https://api.chapchu.site/docs/index.html)에는 로그인/회원가입 엔드포인트가 없습니다.**

이 문서는 브라우저 리다이렉트 기반 OAuth2 흐름을 다루므로, 개별 엔드포인트 명세만으로는 사용법을 알기 어렵습니다.
아래 <<flow>> 를 먼저 읽고 각 엔드포인트 절을 참고하십시오.

[[flow]]
== 로그인 및 회원등록 흐름

=== 기존 회원 로그인

....
[프론트]                    [chapchu-auth]                 [Google]        [chapchu-api]
   |                              |                            |                 |
   |-- 1. /oauth2/authorize ----->|                            |                 |
   |                              |--- 2. 구글 인증 화면 ------>|                 |
   |                              |<--- 3. 인증 성공 -----------|                 |
   |                              |    (DB 조회 → 기존 회원)    |                 |
   |<---- 4. 302 redirect_uri?code=xxx ---|                    |                 |
   |                              |                            |                 |
   |-- 5. /oauth2/token --------->|                            |                 |
   |<---- 6. access_token --------|                            |                 |
   |                              |                            |                 |
   |-- 7. Authorization: Bearer {access_token} --------------------------------->|
....

=== 신규 회원 온보딩

....
[프론트]                    [chapchu-auth]                 [Google]
   |                              |                            |
   |-- 1. /oauth2/authorize ----->|                            |
   |                              |--- 2. 구글 인증 화면 ------>|
   |                              |<--- 3. 인증 성공 -----------|
   |                              |    (DB 조회 → 신규 회원)    |
   |<-- 4. 302 redirect_uri?registration_token=xxx ---|        |
   |                              |                            |
   |    (닉네임 입력 화면 표시)    |                            |
   |                              |                            |
   |-- 5. POST /auth/register --->|                            |
   |      {registrationToken,     |                            |
   |       nickname}              |                            |
   |<---- 6. 200 OK --------------|                            |
   |                              |                            |
   |    → 1번부터 다시 시작 (이번엔 기존 회원으로 처리됨)        |
....

[NOTE]
====
4번에서 `registration_token`이 전달되는 주소는 **FE가 1번에서 보낸 `redirect_uri`와 동일**합니다.
별도의 온보딩 전용 URI를 서버에 등록할 필요가 없으며, FE는 콜백에서 `registration_token` 파라미터가 있으면
온보딩 화면으로 분기하면 됩니다.

`registration_token`은 서명된 단기 토큰(HMAC)으로 `/auth/register` 전용입니다.
====

=== chapchu-api와의 계약

발급된 access token의 `sub` 클레임은 **구글 식별자가 아니라 `users.user_id` (UUID v7)** 입니다.
chapchu-api는 이 값을 그대로 유저 식별자로 사용합니다 (chapchu-api `docs/decisions/016`, `026` 참고).

`JwtClaimsCustomizer`가 `sub`을 내부 user_id로 교체하며, 이 계약은 `TokenEndpointDocumentationTest`가 검증합니다.

== 회원 등록

온보딩 흐름의 5번 단계입니다. `registration_token`을 받은 프론트가 닉네임과 함께 호출합니다.

토큰이 만료되거나 서명이 올바르지 않으면 `400 Bad Request`를 반환합니다.
성공하면 `200 OK`를 반환하고, 곧바로 1번 단계(인가 요청)부터 다시 시작하면 기존 회원으로 처리됩니다.

== 인가 요청

로그인 흐름의 시작점입니다. 브라우저를 이 URL로 이동시키십시오. XHR/fetch로 호출하면 안 됩니다.

미인증 상태면 로그인 페이지로 리다이렉트되고, 로그인을 마치면 `redirect_uri`로 인가 코드가 전달됩니다.

include::{snippets}/oauth2-authorize/http-request.adoc[]
include::{snippets}/oauth2-authorize/query-parameters.adoc[]
include::{snippets}/oauth2-authorize/http-response.adoc[]

[IMPORTANT]
====
`redirect_uri`는 **서버에 등록된 값과 정확히 일치**해야 합니다.
등록되지 않은 값을 보내면 `400 Bad Request`가 반환되며 인가 코드는 발급되지 않습니다.

등록된 주소는 `FRONT_REDIRECT_URI` 환경변수로 관리하며 쉼표로 여러 개 넣을 수 있습니다.
새 주소에서 로그인을 붙이려면 먼저 이 값에 추가해야 합니다.
====

[IMPORTANT]
====
`chapchu-front`는 client secret이 없는 public client이므로 **PKCE가 필수**입니다.
프론트는 요청마다 `code_verifier`를 난수로 만들어 보관하고, `code_challenge = BASE64URL(SHA256(code_verifier))`를 함께 보내야 합니다.
`code_challenge_method`는 `S256`만 지원합니다.
====

[WARNING]
====
**현재 refresh token은 발급되지 않습니다.**

`chapchu-front`는 `ClientAuthenticationMethod.NONE`인 public client인데,
Spring Authorization Server의 `OAuth2RefreshTokenGenerator`는 authorization_code 그랜트를 쓰는 public client에 대해
refresh token 생성을 건너뜁니다.

`RegisteredClient`에 선언된 `REFRESH_TOKEN` 그랜트와 `refreshTokenTimeToLive(14일)` 설정은 실제로 동작하지 않습니다.
따라서 **access token이 만료되는 30분마다 유저가 다시 로그인해야 합니다.**

프론트는 당분간 401 응답을 받으면 인가 요청부터 다시 시작하도록 구현하십시오.
근본 해결은 별도 이슈로 다룹니다.
====

== 디스커버리 문서

issuer와 각 엔드포인트 위치를 담은 OIDC 표준 메타데이터입니다.
chapchu-api는 기동 시 이 문서를 읽어 JWKS 위치를 알아냅니다.

`issuer` 값은 chapchu-api의 `spring.security.oauth2.resourceserver.jwt.issuer-uri`와 **정확히 일치해야** 합니다.
불일치하면 chapchu-api가 모든 토큰을 거부합니다.

[CAUTION]
====
`AUTH_RSA_PRIVATE_KEY` / `AUTH_RSA_PUBLIC_KEY` 환경변수를 비워 두면 **재시작할 때마다 키가 새로 생성**되어
기존에 발급한 토큰이 전부 무효가 됩니다. 운영 환경에서는 반드시 Secret으로 고정 키를 주입하십시오.
====
